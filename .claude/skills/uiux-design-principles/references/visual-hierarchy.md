# Visual Hierarchy

## Core Concept

Visual hierarchy is how you control what users see first, second, and third. It turns a flat collection of elements into a guided experience. Without hierarchy, every element competes for attention and the user's eye has no path — they scan, get overwhelmed, and leave.

## The Hierarchy Toolkit

These are the levers you pull to establish hierarchy, listed roughly by impact:

**Size** — Larger elements attract attention first. Headlines dominate body text. A hero image dominates a thumbnail grid. Scale is the bluntest hierarchy tool but also the most reliable.

**Weight & Contrast** — Bold text on a light background jumps forward. High contrast elements (dark on light, saturated on neutral) read before low contrast ones. Use weight sparingly — if four things are bold, nothing is bold.

**Color** — Saturated or warm colors advance; desaturated or cool colors recede. A single accent color on a neutral page creates an instant focal point. Use color to highlight, not to decorate.

**Position** — Users in LTR languages scan top-left to bottom-right (F-pattern for text, Z-pattern for marketing). Place the most important element where the eye lands first. Critical actions belong in the primary scanning zones.

**Spacing & Proximity** — Generous space around an element isolates it and elevates its importance. Tight grouping signals that elements belong together (Gestalt principle of proximity). Asymmetric spacing creates tension and draws the eye.

**Typography** — A clear type scale (display > h1 > h2 > body > caption) naturally creates multiple hierarchy levels. Font weight, style (italic), and case (uppercase for labels) add further differentiation within a scale.

## The "One Primary" Rule

Every screen, card, or section should have exactly one primary focal point. Ask: "If the user glances at this for 2 seconds, what will they see?" If the answer is "everything" or "nothing in particular," the hierarchy is broken.

**Screen level:** One hero headline or key data point.
**Card level:** One title or metric that justifies the card's existence.
**Section level:** One heading that tells the user what this block is about.

## Squint Test

Blur the screen (literally squint or apply a Gaussian blur). The hierarchy is working if you can still identify the primary element, the groupings, and the general layout. If it collapses into a uniform gray, there's insufficient contrast between hierarchy levels.

## Common Failures

- **Uniform weight:** Everything is the same size, weight, and color. The page reads as a wall of text.
- **Multiple primaries:** Two competing CTAs of equal visual weight. The user freezes (Hick's law).
- **Decoration over function:** Ornamental elements (borders, backgrounds, badges) that are more visually prominent than the actual content.
- **Ignoring empty states:** When there's no data, the hierarchy should still guide the user toward the action that fills the screen (e.g., "Add your first item").

## Applying Hierarchy to Components

**Forms:** Labels above inputs (not inline). Required fields marked. Primary submit button visually dominant; cancel/reset secondary.

**Tables/Lists:** Column headers clearly distinguished from data. Sort/filter controls present but subordinate. The data itself is the star.

**Navigation:** Current page/tab is visually active. Other options are present but recessive. Avoid making navigation louder than content.

**Dashboards:** Lead with the single most important metric. Group supporting metrics. Actions and filters are accessible but subordinate.
